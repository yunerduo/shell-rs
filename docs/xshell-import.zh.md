# 从 Xshell 导入主机

ShellAs 可以直接读 Xshell 的会话：整体导出的 `.xts`、单个 `.xsh`，或者整个
`Sessions` 文件夹。导入只新增主机，不修改已有主机。

## 怎么用

1. 打开左侧主机面板的菜单，选「从 Xshell 导入…」。
2. 对话框默认指向 Xshell 的 `Sessions` 目录（依次找 `文档/NetSarang Computer/8`、
   `7`、`6` 和 `文档/NetSarang/Xshell`）。路径旁有两个按钮：「选择文件…」直接选
   单个 `.xts` 导出或 `.xsh` 会话；「选择文件夹…」改选另一个 `Sessions` 目录或
   解压后的目录。Windows 的系统对话框不能同时选文件和文件夹，所以分成两个按钮。
3. 预览列表里核对名称、分组、地址、端口、用户名和认证方式。库里已有同协议、
   同地址、同端口的主机会标成「已存在」并默认不勾选。
4. 如果这些会话是在启用了主密码的 Xshell 里导出的，可以在列表上方的「主密码」
   里填入那台机器的 Xshell 主密码：能解开的会话会把密码一并写入系统钥匙串。
   留空则和以前一样，只在首次连接时询问。主密码只在这个对话框的内存里使用，
   不保存，导入后立即清空。
5. 点「导入 N 台」写入。导入完成后，主机出现在左侧树里，分组就是 Xshell 的
   文件夹层级。

状态列会标出需要留意的主机：

| 状态 | 含义 |
| --- | --- |
| 需重新输入密码 | Xshell 保存了密码，但没有主密码、主密码不对，或这条会话无法解开；首次连接时会提示输入。 |
| 密码可解密 | 已用主密码解开这条会话的密码，导入后写入系统钥匙串。 |
| 私钥缺失 | 会话指定了私钥，但文件不在 Xshell 的 `SECSH/UserKeys` 里；导入后需要重新指定。 |
| 部分设置未导入 | 会话带有 ShellAs 没有对应概念或没有导入的设置，鼠标停在状态上可看明细。 |

对话框顶部的说明会汇总「多少台需要密码」「多少台私钥缺失」「多少个会话没能导入」。
某个会话读不出来不会中断整次导入，其余会话照常列出；把鼠标停在说明上可以看到
每个被跳过会话的原因。

## 格式是怎么核实的

结论来自本机安装的 Xshell 7 和它生成的真实文件，不是从文档推测：

- `.xsh` 是 INI 文本，Windows 上通常为 UTF-16LE 带 BOM。也兼容 UTF-8（有无
  BOM）和 GBK，因为部分旧版本或中文环境会写成这样。
- `.xts` 的文件头是 `PK`，即 ZIP 容器。条目形如
  `Xshell/<文件夹>/<会话>.xsh`，另有 `Xshell/default.xfs` 等非会话条目。条目名
  没有 UTF-8 标志时按 GBK 解码，否则中文文件夹会变成乱码。
- 字段名来自会话里的 `[CONNECTION]`、`[CONNECTION:AUTHENTICATION]`、
  `[CONNECTION:SSH]`、`[CONNECTION:PROXY]`、`[TERMINAL]` 段。对本机 283 个
  真实会话做过统计：282 个 SSH、1 个 SERIAL，222 个保存了密码，9 个指定了
  `UserKey`。
- `UserKey` 是 Xshell 的密钥名，文件在 `Sessions` 上一级目录（例如
  `文档/NetSarang Computer/7/Xshell`）的 `SECSH/UserKeys/<名字>.pri`；导入时
  按这个位置查找。

## 字段映射

### 导入的设置

| Xshell | ShellAs | 说明 |
| --- | --- | --- |
| `[CONNECTION] Host`（或 `Address`） | 地址 | |
| `[CONNECTION] Port` | 端口 | 缺省时 SSH 用 22，Telnet 用 23。 |
| `[CONNECTION] Protocol` | 协议 | 支持 `SSH`、`SSH1`、`SSH2`、`TELNET`。 |
| `[CONNECTION:AUTHENTICATION] UserName`（或 `User`） | 用户名 | |
| `[CONNECTION:AUTHENTICATION] UserKey` | 私钥 | 只保留能在 `SECSH/UserKeys` 里找到的文件，并生成对应的密钥凭据。 |
| `[CONNECTION:AUTHENTICATION] Password`（非空） | 认证方式「密码」 | 填了主密码时用它解开密码并生成密码凭据；解不开则只标记「需重新输入密码」。 |
| 会话文件名 | 主机名称 | `.xsh` 的文件名去掉扩展名。 |
| 会话所在文件夹 | 分组 | 多级文件夹变成多级分组；单独选一个 `.xsh` 时，如果它在 `Sessions` 下，仍还原它所在的层级；选单个 `.xts` 时，分组取自导出包内的文件夹层级，不会因为选的是文件而丢失。 |
| `[CONNECTION] Description` | 备注 | 原样写入主机的备注。 |

### 明确丢弃的设置

这些字段在 ShellAs 里没有对应概念，或者属于运行期行为，导入时丢弃，并在行的
「状态」里标出「部分设置未导入」，鼠标悬停可看具体是哪几项：

- `Password` / `Passphrase`：加密保存的口令，见下一节。
- 登录脚本：`UseInitScript`、`ScriptPath`、`UseExpectSend`、`ExpectSend_Count`。
- 远程命令：`[CONNECTION:SSH] RemoteCommand`。
- 端口转发：`[CONNECTION:SSH] FwdReqCount` 以及各类 `FwdReq*` / `Tunnel*` 条目。
- 代理：`[CONNECTION:PROXY] Proxy`（含 SSH 会话里的代理配置）。
- 字符集、终端类型、初始目录：`[TERMINAL] CodePage`（非 UTF-8 时）、
  `[TERMINAL] Type`（非 xterm 时）、`[CONNECTION:SSH] InitRemoteDirectory`。
  ShellAs 的终端按自己的设置运行，不跟随单个会话的编码和终端类型。

### 无法导入的会话

- `SERIAL`、`RLOGIN`、`RDP` 等 ShellAs 不支持的协议：跳过并计入告警。
- 没有地址的会话：跳过并计入告警。
- 文件损坏、不是 INI、超过 4 MB：跳过并计入告警。

只有选择 `.xts` 而整个压缩包都打不开时，才会整体报错；包内单个条目损坏不影响
其他条目。

## 密码怎么处理

Xshell 在启用主密码后会把会话密码加密保存：`Password` 是 Base64，解码后是
「密文 + 32 字节校验值」，密文用主密码派生出的密钥做流式加密。ShellAs 按同样
的构造在内存里解开，条件只有一个：用户愿意在导入对话框里填入那台机器的 Xshell
主密码。填入之后：

- 能解开的密码直接交给凭据写入路径，保存进系统钥匙串；主机的认证方式是「使用
  凭据」，数据库里只有引用，不出现密码本身。
- 解不开（没有主密码、主密码不对、会话由别的主密码或别的版本保存）、会话没有
  密码、认证方式不是密码、协议不支持：这一行保持「需重新输入密码」，首次连接
  时正常弹框。不会静默丢弃，也不会写入占位密码。
- 主机地址、用户名与密码解密无关；同一个主密码对导出的所有会话通用。
- 私钥口令不导入；首次使用这把私钥时会提示输入。
- 主密码只在对话框内使用：不写入配置、数据库或日志，导入（或关闭对话框）后
  立即清空。

本机 222 条带密码的会话里，218 条按上述构造解开了。剩下 4 条解不开，原因尚未
查清（可能是更早的 Xshell 版本，或导出时用了不同的主密码），这 4 条按「需重新
输入密码」处理。校验是通过密文尾部与明文摘要的精确匹配做的，不只看解出来的
字节是否可读。

## 已知限制

- 只支持 ShellAs 已有的 SSH 和 Telnet；Xshell 的串口、RLOGIN 等会话会跳过。
- 代理、跳板、端口转发、登录脚本、远程命令不会转换，需要导入后手动配置。
- 已存在判断按「协议 + 地址 + 端口」比较，不比较用户名；同一台机器上不同用户
  的会话会被视为已存在，需要先改端口或手动新建。
- 密码解密只覆盖主密码保护的会话；未启用主密码、或从别的地方拷来的会话，
  仍然按「需重新输入密码」处理。
